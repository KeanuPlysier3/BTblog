I've worked with Web Serial before, so my first idea was to connect the board to the iPad with a cable or Bluetooth. I asked Claude to fact-check that online, and the answer was clear: every browser on an iPad runs on WebKit, and WebKit doesn't support Web Bluetooth or Web Serial. Apple is explicitly against them, for privacy reasons.

That left Wi-Fi, with two options:

1. **The ESP32 talks to the iPad.** The problem: our booth page runs over HTTPS (Safari needs that for the camera), and an HTTPS page isn't allowed to open an unencrypted connection to the ESP32.
2. **The ESP32 talks straight to the server.** No HTTPS problem, and it fits how the game already works: the server decides everything.

I went with option 2. The server now runs a second, small WebSocket server next to the existing one. When an ESP32 connects, it says `hello 1`. When someone presses the button, it sends `pressed`. The server remembers which connection belongs to which booth.

## The hardest part wasn't the code

Writing the code went fairly smoothly. Getting the board online took most of the time:

- **The board manager wouldn't install.** I'd made a typo in the URL: `.jso` instead of `.json`.
- **The upload failed** with "Could not open COM3". I had the wrong port selected. My board has two USB-C ports, and only the one marked "UART" works the easy way.
- **The board only printed dots.** It couldn't connect to the Wi-Fi. We added a scan that lists every network the board can see, and my home network wasn't in it. It turns out the ESP32-S3 can only use 2.4 GHz, and my network is 5 GHz.
- **My phone hotspot wasn't found either,** even though it was right there in the list. The board said "network not found". Claude checked the bytes in my settings file: my iPhone is called *Keanu Plysier’s iPhone*, with a curly apostrophe, and I had typed a straight one. To the board, those are different names.
- **Finally online, but "disconnected, retrying...".** The board was trying to reach my laptop at its address on the home network, but the laptop was now on the hotspot with a different address.

When it finally said "connected to server" and my button press showed up in the terminal, that felt great.

## Working with AI

I used Claude Code a lot for this part, mostly as a teacher. I asked how things work: why `ws.loop()` has to run all the time, why the message gets split on a space etc...  I wrote the server part myself. At one point the AI started editing my server code without me asking, and I stopped it. I want to understand this part, not just have it.

Where it really helped was debugging. I would never have found that apostrophe myself.

It also wrote the README, for the people who will set up the game at the fair. It's based on exactly the problems I ran into: if it happened to me, it can happen to them.

## What I learned

- **The ESP32 only does 2.4 GHz.** Channels 1–13 are 2.4 GHz, and channels 36 and up are 5 GHz.
- **An ESP32 has no event loop.** You keep calling the library in `loop()`, and you never block it with `delay()`.
- **Passwords don't go on GitHub.**  I almost posted my girlfriends wifi network on github before I realised that it was hardcoded in the ino file.
